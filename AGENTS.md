# AGENTS.md

Guidance for AI coding agents (Claude Code, Codex, Cursor, etc.) that use or
change this repository. Humans: see README.md.

## What this is

A single-file Python CLI, `guc_mail_backup.py`, that backs up an Exchange /
Outlook Web App mailbox to local `.eml` files, plus offline tools that work
on a finished backup (HTML viewer, attachment extraction, mbox, stats,
verify). It targets the GUC server (`mail.guc.edu.eg`, Exchange 2016) but
works with any Exchange server that exposes EWS or IMAP.

## Running it as an agent

- **Never run with no arguments.** That starts the interactive wizard, which
  waits for keyboard input.
- **Always pass `--json`.** The result is one JSON object on stdout.
  Progress goes to stderr; add `-q` to silence it.
- **Password:** set `GUC_PASSWORD` or pipe it with `--password-stdin`. If
  neither is set and stdin isn't a TTY, the command fails fast with exit
  code 1. It never hangs.
- **Never print, log, or commit the password**, and never write it to a file
  in the repository.
- **Check before a big run:** use `probe --json` or `backup --dry-run --json`
  first.
- **Resuming is safe.** Re-running the same `backup` command skips saved
  messages and retries failed ones. It never deletes anything, locally or on
  the server; all server access is read-only.

```bash
GUC_PASSWORD=... python guc_mail_backup.py probe  --email X --json -q
GUC_PASSWORD=... python guc_mail_backup.py backup --email X --json -q [--html]
python guc_mail_backup.py stats  --out guc-mail-backup/X --json -q
python guc_mail_backup.py verify --out guc-mail-backup/X --json -q
```

### Exit codes

| Code | Meaning | What to do |
|---|---|---|
| 0 | success | |
| 1 | usage or config error (bad date, no password, no backup found) | read `error` in the JSON |
| 2 | finished, but some messages failed (or `verify` found problems) | re-run the same command |
| 3 | login rejected | ask the user to check the password or pass `--user DOMAIN\name`; do not retry in a loop, because repeated failures can lock the account |
| 4 | server unreachable | ask the user for the host in their webmail address bar and pass `--server` |
| 130 | interrupted | re-run to resume |

### JSON result (all commands)

Every result has `ok` (bool), `command`, and `exit_code`. On failure it
also has `error`. Command-specific fields:

- `backup`: `method` (`ews`/`imap`), `out`, `new`, `had`, `failed`,
  `total_in_backup`, `index`, `folders[]` (`folder`, `new`, `had`, `failed`,
  and `would_download` in dry runs), `would_download`, `dry_run`, and
  `viewer` (with `--html`)
- `probe`: `method`, `items`, and `folders[]` (`folder`, `items`, `class`)
- `html`: `index`, `messages`, `errors`
- `extract`: `out`, `attachments`, `emails_skipped`, `errors`
- `mbox`: `out` and `files[]`
- `stats`: `messages`, `bytes`, `folders[]`, `by_year`, `top_senders[]`
- `verify`: `messages`, `problems[]` (`path`, `problem`), `fixed`

## Backup folder layout (`guc-mail-backup/<email>/`)

| Path | Contents |
|---|---|
| `manifest.jsonl` | Source of truth. One JSON line per saved message: `key` (`ews:<ItemId>` or `imap:<folder>:<uidvalidity>:<uid>`), `folder`, `path`, `subject`, `from`, `date`, `size`. Append-only while backing up; if a key repeats, the last entry wins. |
| `failures.jsonl` | Append-only log of failed fetches (informational only) |
| `mail/<folder path>/<YYYY-MM-DD_HHMMSS>_<subject>_<sha1(key)[:8]>.eml` | Raw MIME, exactly as the server returned it |
| `index.csv` | Rebuilt from the manifest after every backup |
| `viewer/`, `attachments/`, `mbox/` | Generated by `html`, `extract` and `mbox`. Safe to delete and regenerate. |

`guc-mail-backup/` is git-ignored. It holds private mail, so never commit
it or move it into the repository.

## Code map (`guc_mail_backup.py`, top to bottom)

1. **Helpers:** `safe_name`, `parse_date`, `in_range`, and `folder_selected`
   (include/exclude/wildcards/mail-only). `Store` writes `.eml` files
   atomically (`.part`, then rename) and appends to the manifest.
   `read_manifest` and `write_manifest` read and rewrite it. `Progress` shows
   a live line on a TTY and one line per folder otherwise.
2. **Connecting:** `connect()` tries EWS with auto, NTLM, then basic login,
   then EWS autodiscover, then IMAP. It raises `AuthFailed` if any attempt
   rejected the password and `CannotConnect` otherwise. `ews_try` uses
   `FailFast` while probing, then switches the account to
   `FaultTolerance(max_wait=900)` so throttling is waited out.
3. **EWS backup:** `ews_folders` walks `msg_folder_root` plus the archive.
   `ews_backup` lists IDs cheaply, filters them, and fetches MIME with
   `ews_fetch_chunk` in a thread pool; each failed item is retried once on
   its own. Only the main thread writes files.
4. **IMAP backup:** `imap_backup`, single connection. Date filters use IMAP
   `SEARCH SINCE/BEFORE`.
5. **Summaries:** `new_summary`, `add_folder` and `finish` build the JSON
   result.
6. **Offline tools:** `resolve_out`, `make_mbox`, `attachment_parts`,
   `extract_attachments`, `backup_stats`, `verify_backup`, and
   `build_viewer`. The viewer is static HTML with the list embedded as JSON.
   Each message page renders the body in a sandboxed `<iframe srcdoc>`
   (scripts blocked), with `cid:` images inlined as `data:` URIs.
7. **Wizard** (`wizard`): guided mode for non-technical users, run by the
   launchers.
8. **CLI** (`build_parser`, `main`): `main(argv)` returns an exit code and
   is directly testable.

## Conventions

- **Keep it one file** with **exchangelib as the only dependency**. People
  download a ZIP and double-click a launcher, so extra packages or modules
  make that harder. The standard library is fine.
- **Python 3.9+.** The launchers check for 3.9, which exchangelib also requires.
- **Every command returns a result dict** with `ok`. `main()` turns it into
  the exit code and the JSON output. Raise `CliError(msg, code)` for
  expected failures; don't call `sys.exit` inside commands.
- **Human output goes through `log()`** (stderr). Only `main()` writes to
  stdout (the JSON). The wizard uses `print`.
- **Never change the file-name scheme or manifest keys** without a
  migration. Existing backups rely on them to resume.
- **New options go in both places:** `backup_defaults()` (so the wizard and
  tests get a default) and the parser.
- **Server access must stay read-only.** Nothing may move, delete, or mark
  messages as read on the server. IMAP uses `BODY.PEEK[]` and
  `select(readonly=True)`.

## Testing

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
```

The tests are fully offline. `tests/test_guc_mail_backup.py` builds fake
EWS accounts (`FakeAccount`, `FakeFolder`, `FakeItem`) and a fake IMAP
connection, then checks backup/resume/retry, filters, dry runs, connection
fallbacks, every offline command, and CLI exit codes and JSON. Add a test
alongside any behaviour change. The real GUC server can't be reached from
CI or sandboxes, so real-server behaviour can only be confirmed by the user.

Launchers: `Backup my email (Windows).bat` and
`Backup my email (Mac-Linux).command` create `.venv/`, install
`requirements.txt` once (marker file `.venv/installed.txt`), and then run
the script with no arguments. Keep the `.command` file executable
(`git update-index --chmod=+x`).
